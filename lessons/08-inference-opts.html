Inference Algorithm & System Optimisations

Prerequisites

  • Lesson 4 (memory hierarchy, roofline).
By the end you can:
  • Explain FlashAttention and online softmax.
  • Describe PagedAttention and how it eliminates fragmentation.
  • Compare static vs continuous (in-flight) batching.
  • Outline speculative decoding and quantisation families.

1. Concepts

FlashAttention — fuse & tile the \(O(N^2)\) attention

Naive attention materialises the N×N matrix in HBM, then softmax-reads-writes it again, then multiplies by V. That's HBM-thrashing for no good reason.

FlashAttention tiles Q, K, V into SRAM-sized blocks and computes attention block-by-block, never writing the full attention matrix to HBM. It uses online softmax to combine partial maxes/sums across tiles correctly.

Result: same math, ~2–4× faster, drastically less memory, enabling long contexts.

PagedAttention — virtual memory for KV cache

Different requests have different lengths and grow at different rates. A contiguous KV cache wastes memory (over-allocation + fragmentation). vLLM's PagedAttention stores KV in fixed-size pages (e.g., 16 tokens) referenced via a per-request block table — exactly like OS virtual memory.

Benefits: ~0% fragmentation, copy-on-write for shared prompt prefixes (great for beam search / parallel sampling), and seamless preemption.

Continuous (in-flight) batching

Static batching: all requests in a batch must finish before the next batch starts → short requests wait for the longest one (head-of-line blocking).

Continuous batching: at every decode step, the scheduler can remove finished requests and add new ones. The batch composition changes step-by-step. Throughput improvement: often 5–20× over static batching.

Speculative decoding

Use a small fast draft model to propose k future tokens, then verify them with the big target model in a single batched forward pass. Accepted tokens commit; the first rejected one is replaced by the target's sample; the rest are discarded.

Speedup \(\approx\operatorname{accepted\ per\ step}/1\) forward of target. Works because verification is parallel (1 step instead of \(k\)). Variants: Medusa (multi-head draft inside target), EAGLE, lookahead decoding.

Quantisation

Reduce numerical precision of weights (and sometimes activations / KV) to shrink memory + speed up HBM loads.

  • FP16/BF16: training default.
  • FP8 (E4M3/E5M2): H100-class hardware; near-lossless for inference, ~2× faster than FP16.
  • INT8 (SmoothQuant): per-channel scaling to handle outlier activations.
  • INT4 weights (GPTQ, AWQ): calibrated post-training quantisation; activations stay higher precision. ~4× memory reduction.

Disaggregated prefill / decode

Prefill is compute-bound, decode is memory-bound — opposite resource profiles. Run them on separate GPU pools and ship KV cache between them. Improves both TTFT and per-GPU efficiency.

Real-world stack: vLLM = PagedAttention + continuous batching + speculative decoding + quantisation. SGLang and TensorRT-LLM offer comparable stacks. These are why hosted LLM APIs can serve thousands of users per GPU.

2. Socratic check

Why does FlashAttention save memory without changing the math?

It never materialises the full N×N attention matrix in HBM; it computes tiles in SRAM and accumulates a single output, using online softmax to keep numerics correct. The math is identical; the IO pattern is different.

Why does PagedAttention enable cheap prompt-prefix sharing?

Shared prefixes can point to the same physical KV pages via different block tables; only divergent suffixes allocate new pages. Saves memory for systems prompts, few-shot prefixes, beam search siblings.

When does speculative decoding NOT help?

When the draft model's acceptance rate is low (it disagrees often), or when verification compute saturates the GPU (e.g., very large batches already). Net benefit depends on draft quality and batch size.

If INT4 weight quantisation gives 4× memory savings, why isn't it always used?

Some accuracy is lost (especially for instruction-following or math tasks). It also requires dequantisation kernels and may not speed up if your bottleneck isn't HBM bandwidth. Trade off per-deployment.

Key Takeaways

  • FlashAttention: tile + online softmax → no HBM N×N matrix.
  • PagedAttention: virtual-memory KV cache → zero fragmentation, prefix sharing.
  • Continuous batching: per-step dynamic batch → massive throughput gain.
  • Speculative decoding: draft proposes, target verifies in one pass.
  • Quantisation tiers: FP16 → FP8 → INT8 (SmoothQuant) → INT4 (GPTQ/AWQ).
  • Disaggregate prefill (compute) and decode (memory) for efficiency.
