1. Concepts — Agents

The agent loop

An agent is an LLM in a perception–action loop:

while not done: thought = LLM(history) action = parse_tool_call(thought) obs = execute(action) # tool / API / code history += (thought, action, obs) return final_answer

Compare to ReAct (Lesson 9) — agents are ReAct + tool execution + memory + (optional) planning.

Tool use / function calling

The model is shown a list of tools with JSON schemas; it outputs a structured call (name + arguments). Modern models (GPT-4o, Claude, Qwen, Llama-3) are post-trained for this and emit valid JSON reliably.

Memory

  • Short-term: what fits in the current context window.
  • Long-term: a vector store the agent can query (similar to RAG).
  • Scratchpad: intermediate reasoning kept in the prompt.

Planning

For complex tasks, an agent may first plan (decompose into sub-tasks) before executing. Common patterns: plan-and-execute, hierarchical agents, multi-agent collaboration.

Concepts — Parameter-Efficient Fine-Tuning (PEFT)

The motivation

Full fine-tuning of a 70B model needs ~280 GB of optimizer states alone. PEFT freezes the base and trains a tiny number of extra parameters → fits on a single GPU, switchable adapters per task.

LoRA: low-rank adaptation

For a frozen weight \(W\in\mathbb{R}^{d\times k}\), learn a low-rank update \(\Delta W=BA\) where \(B\in\mathbb{R}^{d\times r}\), \(A\in\mathbb{R}^{r\times k}\), with rank \(r\ll\min(d,k)\) (e.g., r=8 or 16).

\[y=Wx+\frac{\alpha}{r}BAx\]

Trainable params per matrix: \(r(d+k)\) instead of \(dk\). For \(d=k=4096\), \(r=16\) → 131k params vs 16.8M (~128× smaller). \(A\) is init random Gaussian, \(B\) init zero (so \(\Delta W\) starts at 0). After training, \(\Delta W\) can be merged into \(W\) for zero inference overhead.

QLoRA

Quantise the frozen base to NF4 (4-bit), keep LoRA adapters in BF16. Enables fine-tuning 65B models on a single 48 GB GPU. Tricks: double quantisation, paged optimisers.

Other PEFT methods

  • Adapters: insert tiny down-project → nonlinearity → up-project blocks; older, slightly slower at inference.
  • Prefix tuning / P-tuning v2: learn task-specific KV "soft prompts" prepended to each layer. No weight modification.
  • Prompt tuning: only learn input-layer soft prompt tokens. Cheapest, weakest.

Modern default: LoRA on attention Q/K/V/O + MLP projections, r=8–64.

Real-world: Hugging Face's peft library, Llama-Factory, Axolotl, Unsloth all default to LoRA / QLoRA for fine-tuning custom LLMs on consumer GPUs.

2. Socratic check

How does an agent know when to stop?

Either the model emits a "final answer" tool call, or it produces text without a tool call, or a maximum-step budget is reached. The loop is controlled by the orchestration code, not the model itself.

Why is B (in LoRA's BA) initialised to zero?

So \(\Delta W=BA=0\) at the start — the fine-tuned model begins identical to the frozen base, ensuring no destructive shift. Training then learns the perturbation.

Why does QLoRA give nearly the same quality as LoRA despite 4-bit weights?

The frozen base weights are only read during forward/backward; gradient signal still flows into BF16 LoRA adapters. The 4-bit quantisation noise is amortised across all weights and turns out to be tolerable for instruction tuning.

If LoRA matrices can be merged into W, why not always train with LoRA?

LoRA caps the rank of the update → less expressive than full fine-tuning. For drastic distribution shifts (new language, new modality) full fine-tuning often wins; for instruction/style adaptation LoRA is plenty.

Key Takeaways

  • Agent = LLM + tools + memory in a thought/action/observation loop.
  • Function calling = structured tool invocation via JSON schemas.
  • LoRA: \(\Delta W=BA\), rank \(r\ll d\), trainable params \(\approx r(d+k)\); \(B\) init = 0.
  • QLoRA: 4-bit base + BF16 LoRA → 65B fine-tuning on one GPU.
  • Merge LoRA into \(W\) for zero-overhead inference.
