Lesson 5 · HIGH priority

Data, Pipeline, Tensor & Optimizer Parallelism

Prerequisites
  • Lesson 3 (transformer block, FFN, MHA shapes).
  • Lesson 4 (collectives, ring AllReduce).
By the end you can:
  • Compare DP, PP, TP, and ZeRO 1/2/3 on what they shard and what they cost.
  • Compute the pipeline bubble fraction for given p and m.
  • Identify the two AllReduces per transformer block in Megatron-style TP.
  • Decide which strategies to combine for a given cluster topology.

1. Concepts

Data parallelism (DP)

Each GPU holds a full copy of the model and processes a different mini-batch slice. After the backward pass, gradients are AllReduced across GPUs, then each takes the same optimiser step.

Pros: simple, near-linear scaling. Cons: model must fit on one GPU; gradient AllReduce volume scales with #params.

ZeRO (Zero Redundancy Optimizer)

Pure DP replicates everything → wasteful. ZeRO shards model state across the DP group:

  • ZeRO-1: shard optimizer states (Adam moments) → ~4× memory saving for Adam.
  • ZeRO-2: additionally shard gradients → ~8× saving.
  • ZeRO-3: additionally shard parameters; AllGather them just-in-time per layer, then drop → memory ≈ 1/N × full. Communication: ReduceScatter for grads + AllGather for params per step.

FSDP (PyTorch) is essentially ZeRO-3.

Pipeline parallelism (PP)

Split the model layer-wise across p stages, one per GPU. A micro-batch flows through stage 0 → 1 → … → p−1. Backward flows in reverse.

Problem: naive pipelining leaves GPUs idle (the "bubble"). Split each batch into m micro-batches to overlap:

bubble_fraction = (p − 1) / (m + p − 1)
  • GPipe: all forwards then all backwards. Simple, peak activation memory.
  • 1F1B (PipeDream): interleave 1-forward-1-backward, smaller activation memory.

Pros: parameter memory split. Cons: bubble, point-to-point comms between stages, requires balanced layer cost.

Tensor parallelism (TP, Megatron-LM)

Split individual weight matrices across GPUs within a layer. Two patterns:

  • Column-parallel: split W along output dim. Each GPU computes its slice of output. No comm needed yet.
  • Row-parallel: split W along input dim. Each GPU computes a partial sum; AllReduce to combine.

In a transformer block, the standard pattern is column-parallel → row-parallel for both the MLP and attention output projection. That gives 2 AllReduces per block (one for attention, one for MLP), in both forward and backward.

TP needs very high bandwidth (it happens inside every layer), so it lives on NVLink within a node, typically TP=2/4/8.

3D parallelism (combining all three)

Real large-scale training uses all together:

  • TP inside a node (NVLink).
  • PP across nodes (a few inter-node hops per micro-batch).
  • DP on top of TP×PP groups, sharded by ZeRO.

Megatron-Turing NLG, Llama-3 405B, etc. all use this 3D arrangement.

Real-world: A 175B model on 1024 GPUs might use TP=8 (within node), PP=8 (8 stages), DP=16. 8×8×16 = 1024.

2. Socratic check

Why does ZeRO-3 save more memory than DP but cost more communication?

It only stores 1/N of params/grads/optimizer states on each GPU (saving memory), but must AllGather full params before each layer and ReduceScatter gradients after — extra comm vs pure DP's single AllReduce.

You have 4 GPUs in a node connected by NVLink and 4 nodes connected by InfiniBand. Where would you put TP and where PP?

TP inside the node (it needs the high NVLink BW because there are 2 AllReduces per layer). PP across nodes (only stage boundaries cross IB, which is fine since point-to-point is much less data than TP's AllReduces).

Increasing micro-batches m reduces the pipeline bubble. What's the cost?

Larger activation memory (more in-flight micro-batches) and longer optimiser-step latency. 1F1B partially mitigates the memory cost.

Key Takeaways

  • DP = replicate model, AllReduce gradients. Simple, but memory-wasteful.
  • ZeRO-1/2/3 shard optimizer / gradients / parameters → big memory savings.
  • PP splits by layer; m micro-batches reduce bubble (p−1)/(m+p−1).
  • TP splits weight matrices; 2 AllReduces per block — needs NVLink.
  • 3D parallel = TP intra-node × PP inter-node × DP/ZeRO on top.
