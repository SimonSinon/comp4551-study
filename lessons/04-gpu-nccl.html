Nvidia GPU Performance & Collective Communication

Prerequisites

  • Basic understanding of bytes, FLOPs, bandwidth.
By the end you can:
  • Distinguish compute-bound vs memory-bound and use the roofline model.
  • Compute arithmetic intensity for a tiny kernel.
  • Name the 4 main NCCL collectives and where each appears in training.
  • Estimate ring-AllReduce cost.

1. Concepts

GPU memory hierarchy

  • HBM (global memory): tens of GB, ~1–3 TB/s. Large, "slow".
  • L2 cache: tens of MB.
  • SRAM / shared memory / registers: ~tens of KB per SM, >10 TB/s. Tiny, blazing fast.

The big secret: HBM bandwidth, not raw FLOPs, is usually the bottleneck. FlashAttention (Lesson 8) wins by keeping data in SRAM and avoiding HBM round-trips.

Compute-bound vs memory-bound

Arithmetic intensity = FLOPs done per byte loaded from HBM.

AI = FLOPs / bytes_moved

Compare to the GPU's compute-to-bandwidth ratio (the "ridge" of the roofline). On an A100, peak FP16 ≈ 312 TFLOPs and HBM BW ≈ 2 TB/s → ridge ≈ 156 FLOPs/byte.

  • If AI < ridge → memory-bound (kernel waits on HBM).
  • If AI > ridge → compute-bound (saturating tensor cores).
Real-world: Big matrix multiplications (e.g., 8k × 8k × 8k GEMM) are compute-bound — that's why LLM training can hit high utilisation. Decoding one token at a time is memory-bound because every matmul is a tall-skinny vector × matrix.

Roofline model

Plot achievable performance (FLOPs/s) vs arithmetic intensity. Two regions: a sloped line (BW-bound) capped by a flat ceiling (compute peak). Optimisations either raise AI (fusion, tiling) or hit higher rooftops.

Why we need collectives

Large models don't fit on one GPU. Training and inference span many devices, which must exchange gradients/activations/parameters. NCCL (Nvidia Collective Communication Library) implements the 4 core primitives over NVLink / PCIe / InfiniBand.

The 4 essential collectives

  • Broadcast: one GPU sends its tensor to all others. Used to ship initial weights.
  • AllReduce: every GPU has a tensor; sum (or average) them so every GPU ends up with the same result. This is the DP gradient sync.
  • AllGather: each GPU has a shard; afterwards every GPU has the concatenation of all shards. Used in ZeRO-3 to reconstruct full params for a layer.
  • ReduceScatter: opposite of AllGather: each GPU ends up with one reduced chunk. AllReduce ≡ ReduceScatter + AllGather.

Ring-AllReduce cost

For N GPUs and message size M bytes on links of bandwidth BW, ring-AllReduce transmits ~2M(N−1)/N per GPU:

T_AllReduce ≈ 2 · (N−1)/N · M / BW

Key insight: cost is independent of N for large N (factor (N−1)/N → 1). That's why ring-AllReduce scales.

Interconnect hierarchy

  • NVLink (intra-node, GPU↔GPU): 600–900 GB/s. Fastest.
  • PCIe Gen4/5 (CPU↔GPU, or older inter-GPU): ~32–64 GB/s.
  • InfiniBand (inter-node, NIC↔NIC): 200–400 Gb/s ≈ 25–50 GB/s.

Topology matters: parallelism strategies are chosen so the heaviest comms stay on the fastest links (NVLink), and rare comms can cross InfiniBand.

2. Socratic check

Why is LLM decoding memory-bound but training is compute-bound?

Training does big batched matmuls (B·N tokens at once) → high arithmetic intensity. Decoding processes 1 token per step, so each matmul is a vector × matrix where you must load the entire weight matrix from HBM to produce a tiny result → low AI → bandwidth-limited.

In data-parallel training, which collective synchronises gradients?

AllReduce — sums per-GPU gradients and distributes the sum to all GPUs so they take the same optimiser step.

If you double the number of GPUs in a ring-AllReduce, does the per-step communication time double?

No. The factor 2(N−1)/N approaches 2 as N grows, so cost is roughly constant in N for fixed message size — that's what makes data parallelism scale.

3. Exercises

Q1. A kernel does 1000 FLOPs and reads 250 bytes from HBM. Arithmetic intensity = FLOPs/byte.

AI = FLOPs / bytes.
1000 / 250 = 4. If the GPU's ridge is ~150, this kernel is heavily memory-bound.

Q2. On an A100 (peak ≈ 312 TFLOPs FP16, HBM ≈ 2 TB/s), the ridge intensity is approximately FLOPs/byte.

Ridge = peak FLOPs / peak BW.
312e12 / 2e12 ≈ 156 FLOPs/byte.

Q3. In data-parallel SGD, gradients are synchronised with the collective .

Sum + broadcast in one op.
AllReduce. Each rank ends up with the summed (or averaged) gradient.

Q4. AllReduce is equivalent to ReduceScatter followed by .

The dual of ReduceScatter.
AllGather. This decomposition is exploited by ZeRO and ring-AllReduce implementations.

Q5. 8 GPUs, message size M = 1 GB, NVLink bandwidth 300 GB/s. Approximate ring-AllReduce time ≈ ms. (Use T ≈ 2(N−1)/N · M/BW.)

2·(7/8) = 1.75. Then 1.75 GB / 300 GB/s.
1.75 / 300 s ≈ 0.00583 s = 5.83 ms.

Q6. Intra-node GPU↔GPU link with the highest bandwidth is .

Faster than PCIe.
NVLink (or NVSwitch in fully connected setups).

Q7. ZeRO-3 reconstructs a layer's full parameters from shards using the collective .

Each GPU holds 1/N of the params; need everyone to see all of them temporarily.
AllGather. After the layer's forward/backward, the full copies are discarded again.

Q8. A kernel with AI = 200 FLOPs/byte on an A100 (ridge ~156) is bound.

AI > ridge means math is the bottleneck, not memory.
Compute-bound. To go faster you'd need higher FLOPs (better hardware) or lower-precision math.

Key Takeaways

  • HBM bandwidth, not FLOPs, is usually the limit.
  • Roofline: AI vs ridge tells you memory- or compute-bound.
  • Training matmuls = compute-bound; decoding = memory-bound.
  • 4 collectives: Broadcast, AllReduce, AllGather, ReduceScatter.
  • Ring-AllReduce cost ≈ 2(N−1)/N · M / BW — almost constant in N.
  • NVLink > PCIe > InfiniBand for bandwidth; place heaviest comms on the fastest link.
