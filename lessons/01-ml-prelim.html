Lesson 1 · Foundation

Machine Learning Preliminaries

Prerequisites
  • High-school calculus (derivatives) and basic linear algebra (vectors, matrices, dot product).
  • Basic Python literacy is helpful but not required.
By the end of this lesson you will be able to:
  • Define features, labels, parameters, and explain what "training" mechanically means.
  • Distinguish supervised vs unsupervised learning and pick the right loss function for regression vs classification.
  • Diagnose overfitting/underfitting using the bias–variance trade-off.
  • Compute MSE and cross-entropy loss by hand for tiny examples.

1. Concepts

What is a model?

A model is a function f(x; θ) that maps an input x (features) to an output ŷ (prediction), parameterised by weights θ. "Training" = automatically choosing θ so that ŷ is close to the true label y on training data.

Supervised vs unsupervised

  • Supervised: dataset is pairs (x, y). Goal: predict y from x. Examples: spam detection, image classification, next-token prediction in LLMs.
  • Unsupervised: only x, no labels. Goal: discover structure (clustering, dimensionality reduction).
Real-world: An LLM is technically self-supervised — labels (the next token) are generated automatically from the input text, so it scales to trillions of tokens without manual labelling.

Loss functions

A loss measures how wrong a prediction is. Lower = better.

Mean Squared Error (regression):

L_MSE = (1/N) · Σᵢ (yᵢ − ŷᵢ)²

Cross-entropy (classification with C classes):

L_CE = − Σ_c y_c · log(ŷ_c)

For one-hot labels, only the term for the true class survives: L = −log(ŷ_true). If the model is confident and right (ŷ ≈ 1), loss → 0; if confident and wrong, loss → ∞.

Train / validation / test split

Typically ~80 / 10 / 10. Train fits θ; validation picks hyperparameters; test gives the final unbiased estimate. Never tune on the test set.

Bias–variance & over/underfitting

  • Underfit (high bias): model too simple → bad on train AND test.
  • Overfit (high variance): model memorises noise → great on train, bad on test.
  • Fixes: more data, regularisation (L2/dropout), simpler model, early stopping.
Real-world: A 70B-parameter LLM trained on only 1M tokens would massively overfit. Chinchilla scaling laws (W4) say tokens should be ≈ 20× params to balance compute vs overfitting.

2. Socratic check (think before opening)

Why do we need a separate test set instead of just judging on training loss?

Because training loss measures memorisation, not generalisation. A model with enough parameters can drive training loss to zero while being useless on new data. The test set is held out to estimate performance on unseen examples.

If your model has 100% train accuracy but 60% test accuracy, what is happening and what would you try first?

Classic overfitting. First try: more data (or data augmentation), then regularisation (weight decay, dropout), then a smaller / less capable model, then early stopping.

Why is cross-entropy preferred over MSE for classification?

Cross-entropy gives a much steeper gradient when the model is confidently wrong, so it learns faster. MSE on probabilities saturates (gradient → 0) when predictions are far from labels, leading to slow training.

Key Takeaways

  • Training = minimise a loss over θ. Loss tells you "how wrong".
  • MSE for regression, cross-entropy for classification.
  • Always split data: train / val / test. Test set is sacred.
  • Overfit = big train–val gap; underfit = both bad.
  • LLM pretraining is self-supervised → unlocks internet-scale data.
