1. Concepts — Inference-Time Scaling

Idea

Instead of (only) scaling training, spend more inference compute per question. Small models with lots of "thinking" can beat big models that answer instantly.

Best-of-N (BoN)

Generate N candidate answers, score each with a verifier (or reward model), pick the best. Strong, simple baseline.

Process reward models (PRM) vs outcome reward models (ORM)

  • ORM: scores only the final answer (e.g., is it correct?). Cheap labels but coarse signal.
  • PRM: scores each step of the reasoning chain. Enables search algorithms to prune bad partial paths.

Tree / MCTS-style search

Treat reasoning as a tree of partial chains. Expand promising nodes (via PRM scores), backtrack from bad ones. Monte-Carlo Tree Search adapts AlphaGo-style search to language.

o1-style reasoning

OpenAI o1 / DeepSeek-R1 are trained with RL on reasoning traces, so the model itself learns to produce long internal chains-of-thought before answering. At inference, you pay for many "thinking tokens", but accuracy on hard reasoning tasks jumps dramatically.

Concepts — RAG

Why RAG?

LLMs have fixed knowledge cutoffs and limited context. Retrieval-Augmented Generation grounds answers in fresh external documents → reduces hallucination, enables private data, no retraining needed.

The 5-stage pipeline

  1. Chunk: split docs into ~200–800 token chunks (often overlapping).
  2. Embed: encode each chunk to a vector with an embedding model.
  3. Index: store vectors in an ANN index (FAISS, HNSW) in a vector DB.
  4. Retrieve: embed the query, fetch top-k nearest chunks; optionally rerank with a cross-encoder for higher quality.
  5. Generate: stuff retrieved chunks into the prompt and let the LLM answer with citations.

Dense vs sparse vs hybrid retrieval

  • Sparse (BM25): classic keyword TF-IDF style. Great when exact terms matter.
  • Dense (embeddings): captures semantic meaning even with different words.
  • Hybrid: combine both (e.g., reciprocal-rank fusion). Usually best in practice.

Reranking

First-stage retrieval = fast and approximate. A cross-encoder reranker takes the top-100 candidates and re-scores each (query, chunk) pair with full attention — slower but much more precise. Keep the top-5 to feed the LLM.

Real-world: Perplexity, You.com, and most "chat with your PDF" tools use BM25+dense hybrid retrieval + reranker + LLM. Modern RAG systems also add query rewriting (the LLM expands the query) and self-RAG (the LLM decides if/when to retrieve).

2. Socratic check

Why is a process reward model more useful than an outcome reward model for search?

Search needs a signal at each partial step to know which branch to expand. ORMs only score completed answers, giving no guidance during the search.

You have a 7B model + lots of inference budget vs a 70B model with no extra budget. When does the small model win?

On problems where verification is easier than generation (math with checkable steps, code with tests), Best-of-N or search lets the small model match or beat the bigger one by sampling many tries and picking the best.

Why does RAG reduce hallucination but not eliminate it?

RAG provides relevant evidence in context, but the LLM can still misread it, blend it with prior beliefs, or copy false retrievals. Hallucination drops sharply but doesn't vanish.

Why is a cross-encoder reranker slower than dense retrieval but more accurate?

Dense retrieval encodes query and doc independently then dots the vectors — cheap. A cross-encoder concatenates query+doc and runs full attention across them — much more expressive but O(N) forward passes per query, so only viable on a small candidate set.

3. Exercises

Q1. Generating N answers and picking the best by a verifier is called .

3-letter acronym.
Best-of-N (BoN). Simple, strong baseline for inference-time scaling.

Q2. A reward model that scores each reasoning step (not just the final answer) is a (acronym).

P for process.
PRM (Process Reward Model). Opposite of ORM.

Q3. Search method named after a board-game algorithm, used for branching reasoning trees: .

Famous from AlphaGo.
MCTS (Monte-Carlo Tree Search).

Q4. The model paradigm trained via RL to produce long internal reasoning before answering is called -style (after the OpenAI model).

OpenAI's reasoning model name.
o1-style (e.g., o1, DeepSeek-R1, Qwen-QwQ).

Q5. The 5 RAG stages in order: chunk → embed → → retrieve → generate.

Build a searchable structure (e.g. HNSW).
Index. Vectors go into FAISS/HNSW/etc.

Q6. The classic keyword-based sparse retrieval algorithm is .

Best Matching, version 25.
BM25. Often combined with dense embeddings in hybrid retrieval.

Q7. A model that re-scores (query, chunk) pairs jointly with full attention is called a reranker.

Contrast with "bi-encoder" (independent encoding).
Cross-encoder reranker. Slower but more accurate than the bi-encoder used for first-stage retrieval.

Q8. Combining BM25 and dense embedding scores (e.g., via reciprocal rank fusion) is called retrieval.

"Mixed" of sparse + dense.
Hybrid retrieval. Usually beats either alone.

Key Takeaways

  • Inference-time scaling: BoN, self-consistency, MCTS, PRM-guided search, o1-style RL-trained reasoning.
  • RAG = chunk → embed → index → retrieve → generate (often with reranking).
  • Hybrid (BM25 + dense) + cross-encoder reranker is the modern default.
  • RAG dramatically reduces but does not eliminate hallucination.
